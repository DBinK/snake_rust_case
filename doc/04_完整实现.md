## 核心代码讲读

### `Phase` —— 状态机写进类型

```rust
pub enum Phase { Ready, Playing, Over }
```

替代 `started: bool + over: bool` 两个标志——`(Ready, over=true)` 这种
非法组合在类型层面就不存在。`turn()` 按 phase 分流：
Ready 阶段收到的方向就是起步方向，Playing 阶段禁反向，Over 阶段转向无效。
`step()` 开头 `if self.phase != Phase::Playing { return; }` 是护栏：
调用方不必记住"哪些阶段能 step"，不变量自己守住。

### `Game::step()` —— borrow checker 唯一会为难你的地方

```rust
let mut body = self.body.iter().copied();
if !will_grow {
    body.next_back(); // 去掉尾格再判咬身
}
// next == head 意味着被 saturating_* 钳在边界原地踏步 = 撞墙；
// 不能靠咬身判：1 节蛇时尾格已被去掉，原地踏步会漏判成"卡住不死"。
let hit_self = next == self.head() || body.any(|p| p == next);
```

对 C/Python 读者：这看起来就是"复制一份蛇身再查包含"，
但 `iter().copied()` 是**零拷贝视图** —— 编译器要保证你在
拿着只读借用迭代时，没人同时 push/pop 这个 VecDeque。
顺序写成"先 push_front 再判咬身"会立刻被借用检查器拦住：
你要么把顺序排对（本来也该排对），要么显式 clone。

这就是 Rust 那句"借用规则逼你写正确的代码"最具体的一次演示。

> 教学注记：`next == head` 这行是真实修过的 bug——`saturating_sub`
> 会把越界钳到边界格，1 节蛇贴边反向会原地卡住永远不死。
> 这个 bug 的回归测试 `dies_when_pinned_to_edge` 就在文件底部。

### `enum Input` —— 把控制流收进类型

```rust
pub enum Input { Move(Dir), Quit, Retry }
match read_input(tick_for(g.score))? {
    Some(Input::Quit) => break,
    Some(Input::Move(d)) => g.turn(d),
    _ => {}
}
```

C 的等价物是"返回 int，0=没键，1=移动，2=退出"，靠注释约定；
Python 是"返回 tuple 或 None"，靠文档约定。这里四种结果
是**同一个类型的四个形状**，`match` 漏一个臂编译器点名。

`Move(Dir)` 还能**带数据** —— C 的 tagged union 要自己管内存和标签，
Rust 的 enum 自带判别，拆包时拿数据不可能错配。

### `impl Drop for RawMode` —— RAII 落点

```rust
impl Drop for RawMode {
    fn drop(&mut self) {
        let _ = execute!(io::stdout(), cursor::Show, LeaveAlternateScreen);
        let _ = terminal::disable_raw_mode();
    }
}
```

Python `curses.wrapper` 干的就是这件事；C++ 的 RAII 同理。
Rust 的特殊之处：`let _guard = RawMode::enter()?` 之后，
**任何** `?`/`panic`/正常 return 都会触发 `drop`，
终端一定恢复 —— 你不用像 C 那样在每个错误出口手动配对。

### `Option<Input>` vs Python 返回 None

```rust
pub fn read_input(timeout: Duration) -> io::Result<Option<Input>>
```

Python 惯例"没按键返回 None"在这里被写成 `Option<Input>`：
`None` 不再是"碰巧返回了 None"，而是签名里明说的可能性。
调用方 `match` 时必须给出 `None` 分支，想忘都忘不掉。

## 主循环：三态驱动

```rust
loop {
    draw(&g)?;
    match g.phase {
        Phase::Ready =>   // 只等按键，蛇不动
        Phase::Playing => // tick_for(score) 一帧：读输入 → step → draw
        Phase::Over =>    // 结算屏：r 重开 / q 退出
    }

Ready 屏等第一个方向键才起步——这正好是 `Phase` 枚举价值的第二次体现。

## 单元测试为什么容易

`Game` 不碰 I/O —— 构造函数、turn/step/打分全是纯逻辑，
`#[cfg(test)]` 模块直接 `use super::*` 就地测。
这是分层给的回报，也是 Rust 鼓励的结构：**把可测的和不测的分清楚**。

## 2024 edition 顺手出现的新语法

- `let ... else`（examples/minimal.rs 用过）：模式不匹配时早退
- `if let Some(x) = opt` / `match` 嵌套 `Option` + 自定义 enum 的模式组合（本文件到处都是）
- `matches!(g.phase, Phase::Over)`：测试里只判变体不取值
- `edition = "2024"`：Cargo.toml 里一行的事，无感升级

# 01 需求规范

## 核心愿景

贪吃蛇是一款规则直观、人人皆知的经典游戏。选择贪吃蛇作为 Rust 的学习载体，核心目的在于**降低业务逻辑的理解门槛，将全部认知资源集中在 Rust 的核心语言特性上**。

在实现过程中，开发者将完整经历：
- 终端底层 I/O 控制与 Raw Mode 模式管理。
- 类型驱动的状态机设计。
- 所有权与借用检查器在数据迭代与更新时的约束机制。
- 基于 RAII 的确定性资源清理。
- 表达式、代数数据类型与穷尽模式匹配。

## 游戏规则与功能清单

### 1. 棋盘与坐标系

- 棋盘采用固定尺寸：宽 20 单元格，高 12 单元格。
- 坐标原点 `(0, 0)` 位于棋盘左上角，水平向右为 x 轴递增，垂直向下为 y 轴递增。
- 字符渲染映射：
  - 蛇身节点表示为 `O`。
  - 食物表示为 `*`。
  - 空白区域表示为 `.`。

```
  Score: 3   (h/j/k/l or arrows, q to quit)
  ....................
  ....................
  ..........*.........
  ....................
  ........OOOO........
  ...........O........
  ....................
  ....................
```

### 2. 状态流转与交互机制

游戏生命周期明确分为三个阶段：

- **Ready 阶段（就绪等待）**：
  - 初始时蛇身长度为 1，位于棋盘正中心 `(10, 6)`，默认朝向右侧。
  - 蛇身静止不动，界面提示等待起步按键。
  - 玩家按下任意方向键（方向键或 `h`/`j`/`k`/`l`）即设定行进方向并立即进入 Playing 阶段。
- **Playing 阶段（正常行进）**：
  - 蛇身按照当前设定的时钟节拍匀速步进。
  - 允许在步进间隙变更方向。
  - 严格禁止 180 度直接掉头：行进方向向右时按下左方向键视为无效输入，保持原方向行进。
- **Over 阶段（游戏结算）**：
  - 发生碰撞判定后进入结算界面。
  - 屏幕显示最终得分，支持按 `r` 或回车键重开游戏，按 `q` 或 `Esc` 键退出程序。

### 3. 时序节拍与动态调速

- 初始起步节拍为 200ms。
- 蛇身每吃掉一块食物，节拍缩短 10ms，提高游戏紧迫感。
- 节拍下限设定为 60ms，防止速度过快导致不可操控。
- 输入采集采用非阻塞轮询，仅在节拍周期内暂存最新有效转向，避免快速敲击时事件堆积失控。

### 4. 食物生成与得分

- 食物必须在未被蛇身占据的空格中生成。
- 采用无偏均匀随机抽样，确保不会产生空间概率倾斜。
- 蛇头移动至食物所在单元格时：
  - 得分累加 1 分。
  - 蛇身在尾部保留原单元格，长度自然增加 1 节。
  - 棋盘剩余空格中立即生成下一块食物。

### 5. 碰撞检测规则

发生以下任一情况时，当前生命周期终止并转入 Over 阶段：

- **越界撞墙**：蛇头移出 `[0, WIDTH)` 或 `[0, HEIGHT)` 的坐标范围。
- **自体咬合**：蛇头移入已有蛇身所在的坐标格。需要注意，若步进时未吃到食物，原本的尾节点会在当前节拍移出，因此移动到即将让出的尾节点坐标不属于咬到自身。

### 6. 终端环境清理保障

终端程序必须具备严密的退出保障：
- 无论正常退出、主动放弃、游戏结束还是程序异常退出，终端必须可靠退出 Raw Mode，切回标准屏幕缓冲区，并重新显示输入光标，防止终端处于击键无回显的损坏状态。

## 明确非目标

为了保证核心教学密度，以下特性被显式排除在本项目之外：
- 不做分数持久化存储与历史排行榜。
- 不做多关卡、复杂障碍物与多样化道具。
- 不做多色彩终端主题渲染与复杂动画。
- 不做音频输出与多线程背景音乐播放。

所有省下的周边复杂度，都服务于深入理解 Rust 的内存安全与类型系统。

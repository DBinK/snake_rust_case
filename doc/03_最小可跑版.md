# 03 最小可跑版：终端交互原型

开发终端游戏最大的门槛并非游戏规则本身，而是**如何与终端进行低层交互**。在常规命令行程序中，标准输入以行为单位缓冲，用户敲击回车前程序无法捕获按键，敲击的字符还会自动回显在屏幕上。

本章通过 `examples/minimal.rs`（共 56 行代码），剥离所有贪吃蛇业务逻辑，仅关注三件事：**进入原始模式、读取键盘事件、在屏幕指定位置绘制字符**。

## 运行体验

执行以下命令启动最小原型：

```bash
cargo run --example minimal
```

运行后屏幕上会出现一个 `@` 字符，可以使用键盘方向键控制其上下左右移动，按 `q` 或 `Esc` 退出。

## 核心机制拆解

### 1. 终端模式切换与交替屏幕

```rust
terminal::enable_raw_mode()?;
execute!(io::stdout(), terminal::EnterAlternateScreen, cursor::Hide)?;
```

- **Raw Mode（原始模式）**：
  - 常规模式（Cooked Mode）下，输入必须等待换行符且会自动回显。
  - 开启 Raw Mode 后，终端驱动层关闭行缓冲与自动回显，按键事件会实时送达程序。
- **EnterAlternateScreen（交替屏幕）**：
  - 终端支持两组屏幕缓冲区。切换到交替屏幕缓冲区后，程序的所有绘制均在新视口完成，退出时切回原缓冲区，用户的 Shell 历史记录与上下文完全不受污染。
- **cursor::Hide（隐藏光标）**：
  - 避免闪烁的输入光标破坏游戏画面表现。

### 2. 双缓冲批量刷盘

```rust
queue!(
    stdout,
    terminal::Clear(ClearType::All),
    cursor::MoveTo(x, y)
)?;
stdout.write_all(b"@")?;
stdout.flush()?;
```

频繁向标准输出发起单字节写入会导致大量的系统调用（syscall），造成终端画面闪烁甚至卡顿。
- `queue!` 宏将清屏与光标跳转等转义序列写入内存缓冲区。
- 随后调用 `stdout.flush()` 一次性向终端下发整批指令，显著提升渲染性能并消除撕裂感。

### 3. Rust 2024 `let-else` 语法处理事件流

```rust
let Event::Key(key) = event::read()? else {
    continue;
};
```

终端事件不仅包含按键，还包含窗口尺寸变更（`Event::Resize`）及鼠标移动等。
在以往语法中，通常需要书写嵌套的 `if let` 块：

```rust
// 传统嵌套写法
if let Event::Key(key) = event::read()? {
    // 嵌套缩进加深
}
```

Rust 2024 支持 `let-else` 结构：当模式解构匹配失败时，直接执行 `else` 块（必须包含早退发散表达式，如 `continue`、`break` 或 `return`），从而使后续正常逻辑保持在同一缩进层级。

### 4. 穷尽模式匹配与分支组合

```rust
match key.code {
    KeyCode::Up => y = y.saturating_sub(1),
    KeyCode::Down => y += 1,
    KeyCode::Left => x = x.saturating_sub(1),
    KeyCode::Right => x += 1,
    KeyCode::Char('q') | KeyCode::Esc => break,
    _ => {}
}
```

- **穷尽性保证**：Rust 编译器掌握 `KeyCode` 枚举的全部变体，开发者必须显式处理或者使用 `_` 兜底，杜绝无意识遗漏。
- **模式组合 `|`**：通过 `|` 连接多个候选模式，一行即可处理多种退出按键。
- **饱和减法 `saturating_sub`**：坐标类型采用 `u16`（无符号整数）。直接执行 `y - 1` 在值为 0 时会导致下溢（在调试模式下 panic，在发布模式下隐式回绕成 65535）。`saturating_sub(1)` 在达到数值下限 0 时保持为 0，以声明式手段筑牢数值边界。

### 5. 原型遗留的隐患与 RAII 的必要性

查看 `examples/minimal.rs` 的退出逻辑：

```rust
execute!(stdout, cursor::Show, terminal::LeaveAlternateScreen)?;
terminal::disable_raw_mode()
```

这种手动恢复终端的方式存在严重隐患：如果在主循环中发生 `panic`，或者某个 I/O 操作由于 `?` 提前返回，恢复逻辑就会被跳过，导致用户的终端 Shell 处于光标消失且按键无回显的瘫痪状态。

在第 04 章中，我们将把这一底层生命周期封装进 `RawMode` 结构体并实现 `Drop` 特征，借助 RAII（资源获取即初始化）机制保证无论程序如何退出，终端均能确定性恢复。

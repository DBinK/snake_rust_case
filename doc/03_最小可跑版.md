# 03 最小可跑版：56 行学会终端交互

先看 `examples/minimal.rs`，只有三件事：**进 raw mode → 读键 → 画字符**。
跑一下：`cargo run --example minimal`，方向键移动 `@`，q 退出。

## 逐段对照

### `terminal::enable_raw_mode()?`

- C：你要手写 `tcgetattr`/`tcsetattr` 关 ICANON 和 ECHO。
- Python：`curses.noecho()` + `cbreak()`。
- Rust：一行调用，但注意 —— **它不是 RAII**，函数结尾必须配对 `disable_raw_mode()`。
  这就是为什么第 04 章把这段包进 `RawMode` struct + `Drop`：
  作用域结束自动归还，连 `?` 提前 return 都不漏。
  （第一次体会"Rust 逼你把资源生命周期想清楚"。）

### `let Event::Key(key) = event::read()? else { continue }`

- 2024 edition 的 `let-else`：模式匹配不上就走 else 分支。
- 替代 `if let Event::Key(k) = e { ... }` 的嵌套，把"不关心的分支"压扁。
- 对 C/Python 读者：相当于 `if not isinstance(...): continue`，但这是**编译期**模式匹配，
  `event::read()` 的返回类型里根本没有别的形状，else 只处理 Key 以外的 Event 变体。

### `match key.code { ... _ => {} }`

- `match` 必须**穷尽**：`KeyCode` 有多少变体编译器全知道，漏一个就报错。
- `_` 兜底 = C 的 `default`；`| ` 模式或：`Char('q') | Esc` 一行两个键。
- 对比 C 的 `switch`：漏 `break` 会贯穿，漏 `default` 没人管；这里全都不允许发生。

### `y = y.saturating_sub(1)`

- `u16` 是无符号，减到 0 以下在 C 里会回绕成 65535 然后踩墙；
  `saturating_sub` 让结果钉在 0 —— 把"防下溢"写进操作本身。

## 到这一步你会了

- `?` 传播错误（不是异常，是编译期强制的 Result）
- `match` 穷尽 + `|` 模式 + `_` 兜底
- `let-else` 早退
- `u16`/`saturating_*` 这组"把不变量编码进类型"的思路
- 为什么 RAII 重要（下一章就用到）
